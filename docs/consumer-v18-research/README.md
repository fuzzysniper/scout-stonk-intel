## What works

`/research/cards` is a real Next.js route linked from the existing consumer footer. It calls the existing, validated `/api/pairs?quoteMint=CARDSccUMFKoPRZxt5vt3ksUbxEFEcnZ3H2pd3dKxYjp&discovery=pair` once on entry. It does not add an API, provider adapter, stored dataset, collector, recurring network poll, credential or RPC path. Existing backend caching, admission, source-age, timeout, byte, two-page and 12-mode-check budgets remain authoritative.

The reader can discover actual exact-mint CARDS pair identities, search only within the returned sample by name/ticker/exact address, inspect exact pool/quote identities and source receipts, and distinguish separately checked reward settings from unchecked catalog mode. Alphabetical order expresses identity, never economic leadership. Empty, inaccessible and malformed responses are different states. A failed source never displays a zero-token universe or the last successful result as a fresh answer. Old source responses are labeled dated; source response generation/retrieval is never labeled market observation time.

A separate manual exact-mint lookup, also available as `/research/watch?mint=<mint>`, reuses `/api/token?mint=<mint>`. It shows the selected pool's base/quote identities, provider, original adapter retrieval time and verification limits. A quote-side match cannot inherit the base token's name, cap, price change or performance. No market match is not proof that a mint is invalid. No background monitoring or saved watchlist is implemented. Clipboard access requires a deliberate gesture; it never submits automatically. Editing, back/forward navigation and unmount cancel/discard old work. Share URLs open the generic `/research/watch` route, contain only the requested address, and do not trigger CARDS discovery. Reopening restores the field and requires an explicit lookup. URLs and the server's ordinary request logs may expose that address: private research links should not be shared publicly. No analytics or browser persistence is added.

## Performance metric definitions and strict offline policy

`app/consumer/cards/performance.ts` is pure, bounded preparatory calculation logic; it makes no source requests and is not an alternate backend contract. Its successful paths are exercised with explicitly labeled synthetic offline tests. **The real UI has no CARDS market-history producer and never consumes synthetic points or renders offline ranks.** Every prepared calculation result still says `publication: withheld_pending_rights_review`; the function cannot grant publication permission.

| Metric / gate | Exact definition and limitation |
| --- | --- |
| Compatible identity | Distinct exact base mints and distinct pools, same pinned, registry-confirmed CARDS quote mint (the current offline policy rejects other universes). Names/tickers never join universes. Price input is explicitly denominated in that quote token, not mixed USD/CARDS prices. |
| Common window | Exactly 24 hours, identical actual start/midpoint/end observations. At least 25 strictly increasing points, at most 1,000 per series, no gap above 90 minutes, no duplicates, no interpolation or fabricated boundaries. |
| Freshness / provenance | End no more than 90 minutes before evaluation; future evaluation/window rejected. Each point requires actual market-observation kind, HTTPS source without credentials/fragment, consistent source URL per series and SHA-256 revision shape. Hash shape cannot independently authenticate an input; a future reviewed adapter must establish source identity, rights, capture integrity, pool continuity and actual observation semantics. These functions are not source attestation. |
| Observed appreciation | `(end quote price − start quote price) / start quote price × 100`. Positive canonical decimal prices, up to 18 decimal places, integer arithmetic; percentage truncated toward zero to six decimal places. No float-based price ratio. Not a trading/holder return; fees, execution/slippage, transfer taxes and cashflows absent. |
| Observed peak | Maximum of sampled quote prices inside the stated window only. Drawdown is `(end − sampled peak) / sampled peak × 100`; never called an ATH or proof of intra-sample extremes. |
| Comparison | All submitted candidates must pass the same window. Any ineligible candidate withholds the whole comparison; no quietly dropping losers. At most 50. Six-decimal percentage ties share competition rank, deterministic exact-mint tie order. Always a partial selected sample; no ecosystem leader. |
| Market capitalization | Unavailable in the existing pair contract. Requires a separately reviewed exact-token supply/circulation definition, actual aligned price/supply clocks, source rights and comparability. FDV cannot silently substitute for circulating market cap. No cap leaderboard is implemented from untimed upstream fields. |
| Reward activity / participation | Separate mechanism, lifetime, covered interval and holder-entitlement tiers remain separate. No mint/holder count inferred from volume, no unique-trader/paid-wallet claims. No CARDS covered reward interval or current holder series established. |

### Retrospective momentum policy

This is a conservative, unvalidated research rule, not an investment signal or prediction. Both aligned 12-hour halves use actual endpoints. Every observation must also report finite liquidity >= USD 10,000 and trailing 24-hour volume >= USD 1,000; trailing volume snapshots are context, not disjoint interval flow or participant counts.

* **Early emerging:** first half between −3% and +3%, second half >= +10%, ending no more than 5% below the sampled peak.
* **Sustained expansion:** both halves >= +10%, with >=80% of recorded prices at or above the window's start.
* **Consolidation:** first half >= +10%, second half between −3% and +3%, ending no more than 20% below sampled peak.
* **Weakening:** first half >= +10%, then second half <= −10% or end at least 20% below sampled peak. Evaluated first so a visible reversal cannot retain expansion status.
* **No clear pattern:** price/context coverage passes, none of those patterns meets its thresholds.
* **Insufficient evidence:** failed identity, period, freshness, source, coverage or liquidity/volume context. Missing context can withhold momentum while the pure price calculation remains an unpublished observed change.

These thresholds are explicit policy choices, not empirically validated predictive relationships. They cannot compensate for pump/spike manipulation, missing trades or sparse samples. No live momentum label is supported by today's CARDS dataset.
