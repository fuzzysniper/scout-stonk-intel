## What now works

`/research/cards` still discovers a bounded, non-atomic, provider-selected exact-CARDS sample through the existing `/api/pairs?quoteMint=…&discovery=pair`. It now computes **comparison eligibility from the actual validated response**: sampled-token count, price/liquidity/volume field-presence counts, zero qualified price-history points, and precise reasons each pair cannot be ranked. These are evidence counts, not returns. Source failures show no eligible-token count rather than implying an empty ecosystem. Details separate transport/source clocks, market timestamps, source precision, market-cap definition and publication permission. No extra browser/provider request or background poll was added. Prices, ranks and momentum are never manufactured from discovery order.

A runnable offline pipeline verifies bounded local capture bytes, normalizes the actual official single-token response without losing original decimal lexemes, checks exact token/quote/pool/network and registry identity, and produces a **metadata-only insufficiency report**. [The genuine execution](actual-inspection.json) normalized one actual GACHA pool snapshot; it admitted **zero** public price observations. Hashes are integrity checks against supplied bytes, not publisher authentication.

The pure calculation layer now requires identical hourly sampling, calculates chronological maximum drawdown separately from ending drawdown, orders comparisons using exact ratios, and evaluates momentum thresholds without rounding. Successful calculations remain offline rehearsals; synthetic data cannot enter the genuine inspection path or public financial output. There is no release override for rights or a fixture-to-live flag.

**Genuinely supported comparisons today:** discovery identity, metadata/coverage and field-presence comparisons within the loaded sample. **No observed price-appreciation, drawdown, sampled-peak, cap or momentum leaderboard is supported.** There are no qualified actual CARDS price points, let alone a common 24-hour series. Lifetime reward counters are neither prices nor holder returns.

## Access and publication rights — separate unresolved gates

Public GET capability establishes neither retention nor redistribution/commercial rights. The current OpenAPI supplies no license. The developers HTML did not establish such permission; its terms modal was not revalidated. Prior dated [terms research](../PAIR_DISCOVERY_COVERAGE.md#published-access-terms) and [historical rights gate](../HISTORICAL_RESEARCH.md#rights-and-retention-decision--blocked-not-inferred) remain unresolved, not current consent. Gecko and Dex permissions could not be qualified. **No source-derived financial quantities are published by this change.** No copied OHLC/cap/change/peak values, raw bodies or source charts are committed.

The new report allows only exact identities, clocks, source links/hashes, counts and withheld reasons. Mathematical coverage cannot unlock publication. Owner/provider review of retention, derived metrics, metadata publication and commercial use is required before a genuine-data pilot. Existing API JSON may still expose pre-existing financial fields in Network; this PR does not change those APIs or remediate their prior rights status. October 14 consumer examples remain separate, stale and under their original restrictions.

## Boundaries and risks

No new real-data history producer exists. No provider source has been qualified for actual quote-price time semantics. The pipeline cannot retrospectively establish a missing tick by repeatedly capturing an untimed snapshot. An operator-supplied body/hash is not a signed provider attestation. Partial provider-selected samples, migrating/duplicate pools, source revision/caching changes, price manipulation and unvalidated momentum thresholds remain material limits. Source URLs can change. Private research addresses must not be committed or shared; this work contains only public source catalog identities and labeled offline fixtures.
