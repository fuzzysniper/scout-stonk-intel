## What is actual code

- `lib/v4-owner-ledger/auth.ts`: Better Auth **1.7.14** validates the real signed opaque session cookie against native PostgreSQL on every request; cookie cache and session refresh disabled. Signature alone is insufficient. Exact session issuer/audience, fresh expiry, immutable one-owner subject and journal-owner mapping must all match the separately provisioned database policy. Authenticated nonowners fail. Request-local capability is opaque/WeakMap-bound, expires within one second and must not be reused on another request. Revocation/deletion and policy disable are rechecked on each request; a second DB lookup checks session existence/expiry after library validation. Revocation during an already running authorized operation is not retroactive cancellation.
- `contract.ts`: shared **type-only** `VerifiedOwnerContext` / `VerifiedOwnerPort.verify(request)` and `inspect(context)` seam for B #228. No cast into legacy `OwnerAuthority`. B must consume this same port and exact `journalOwnerId`; an injected mock is never a genuine issuer. Integration needs separate review. B #230 uses a different storage-principal wrapper (`resolve/verifyCsrf/isCurrent`), not an interchangeable A context. A never casts its context/UUID into J's `VerifiedOwner`; the actual legacy capability/CSRF bridge remains HOLD.
- `ledger.ts` + `schema.sql`: actual transactional `pg` adapter implementing P's existing `GlobalLedgerPort`. One isolated singleton policy, durable row lock, native TLS/SNI/CA/SCRAM, `fsync=on`, synchronous COMMIT, pinned SQL body/owner/search_path/role compatibility, ACK before output. No memory fallback, schema/bootstrap action, reset, refund, retry or lease reclaim.
- SQL owns **30 total read/cache admissions, 10 irrevocable attempt reservations, <=15 minutes, exactly three exact decoded 32-byte mints, cumulative conservative integer credits and one unresolved lease**. Reports bind original hash, slot and receipt time. Cache uses still consume a read and must match a prior report, <=30 seconds old; source age <=60 seconds. The old engine retains its stricter full checks. No facts are collected by this adapter.
- A permanently fenced process may serve multiple verified sessions of the same owner. A **new/competing adapter cannot inherit that fence**: it commits STOP. This deliberately sacrifices failover/availability for the bounded pilot; do not reconstruct a ledger on every request. Instantiate once per approved worker lifetime. There is no resume/reset protocol.
- Before COMMIT, a crash rolls back the proposed change. After COMMIT, reservations survive immediate PostgreSQL crash/WAL recovery. Lost/uncertain ACK yields no result, latches the process closed and attempts STOP once. If that STOP cannot be durably acknowledged (e.g. partition or queue saturation), no durable STOP success is claimed: the persistent fence and unresolved lease still prevent restart/takeover. Every already-running operation withholds its response after the local latch closes. A later fresh instance stops instead of continuing. This does not claim synchronous replication, regional survival or PITR safety.
