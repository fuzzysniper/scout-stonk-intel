# Deterministic signal rule proofs

All values below are synthetic arithmetic examples, never current token facts. Every rule is scoped to one selected exact base/quote/pool in a bounded provider sample. Every successful financial computation retains `market_observation_time_unknown` and `state=uncertain`; no provider reports become independently observed trades.

Synthetic proof: 5m buys=30/sells=10 and 1h buys=180/sells=60 produce rates 8/min vs 4/min, ratio2 and imbalance0.5. Same ticker never identifies a token; an unrelated mint with that ticker fails validation. Mirroring buys/sells negates imbalance and leaves activity unchanged. On the deterministic count lattice, imbalance remains bounded [-1,1], and for consistent nested windows activity ratio stays [0,12]. A zero hour and zero five-minute count produce null ratio and `no_reported_activity`, not infinity; no transactions produce unavailable imbalance. No figures represent holder returns or historical flows.

## Binary clock tests

`retrievedAt` means the **entire response body was received**, not request start, provider calculation, trade execution or blockchain confirmation. Raw bytes hash is bound to that source request. `providerObservedAt`, `underlyingTradeAt` and `windowEndAt` remain null. Extra envelope `timestamp/updatedAt/observedAt`, HTTP Date/Last-Modified/Age and `pairCreatedAt` cannot qualify them. No concrete UTC trade intervals are fabricated from m5/h1 labels. Aggregation orientation/window definitions still require provider confirmation.

An explicit evaluation before retrieval or more than60s after retrieval withholds all financial calculations and adds a time-quality flag. That60s limit is **local retrieval expiry**, not proof of fresh market state. Pool age uses retrieval as the reference and is explicitly uncertain. No clock allows an expired packet to refresh itself. Re-evaluation at the same explicit time is deterministic, and frozen inputs cannot mutate into another mint/amount after validation.
