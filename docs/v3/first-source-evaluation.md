## SEC-P1: the ONE proposed pilot, still inactive

**Question:** For one independently selected issuer, what is the newest supported filing **in the returned recent subset**, when was it accepted/filed, what period does it describe, and where can the owner verify it? Initial forms: US10-K/10-Q/8-K and their `/A` amendments. Foreign reports, XBRL quantities/ratios, market prices, classifications, trading, broad discovery and full filing/exhibit text are excluded. A filing receipt is not a valuation, up-to-the-minute fundamentals, source-backed PLAN approval or company truth certification.

**Identity:** owner supplies a confirmed ten-digit nonzero CIK and an explicitly user-asserted MIC/ticker listing reference, together with the primary record supporting that association. No CIK/ticker lookup request, guessed exchange, issuer/share-class equivalence or ticker→mint mapping. A future response must match the requested parent issuer CIK. The filing accession's submitter prefix must not be used as an invented issuer match. CIK can cover multiple listed securities; unresolved issuer→security association stays unverified. If that distinction does not satisfy the intended research question, stop before acquisition.

**Proposed request envelope — a specification, NOT an executable command or verified wire contract:**

| Control | Exact proposed boundary |
| --- | --- |
| Invocation | One explicitly owner-approved session, one deliberate Research action on the chosen issuer. No typing/on-load/history/refresh/prefetch acquisition |
| Target | One `GET https://data.sec.gov/submissions/CIK<ten-digit-CIK>.json`, fixed host/path, no query, credentials, POST or provider substitution |
| Headers | Accept application/json; owner-approved truthful public contact/User-Agent only after current SEC access policy is reviewed. No invented email, key or contact |
| Admission | At most **one total wire attempt**, one concurrent request, retries0, redirects0, one approval token/session consumed even on error. Double-tap, refresh or runtime restart must not reset admission. No such admission implementation is delivered here |
| Time/bytes |10,000ms total deadline;2,097,152 decoded bytes including decompression; malformed/oversized/redirect/403/429/5xx stop, no fallback/backfill. Respect explicit Retry-After without scheduling a retry |
| Projection | Proposed future parser inspects at most1,000 recent rows, retains at most8 supported-form rows for local normalization, no archived `filings.files` pagination, companyfacts, HTML/exhibit or secondary calls. Current official schema must first be verified; reject parallel-array/identity/clock ambiguity |
| Cost | Provider-fee ceiling **$0.00**, current source price unverified. No account, card, subscription, overage or paid request. Hosting/logging also must fit separately approved existing entitlement; no new spending. Unknown economics =NO-GO |
| Cutoff/revocation | Source disabled before and after the single session. Owner cancellation prevents an unsent attempt; aborting a sent request cannot un-spend it. Any unclear attempt is consumed, not retried. Missing authorization, rights, attribution or meter/cost confidence fails closed |

**Clocks and provenance:** capture original acceptance instant only when its source timezone is explicit; do not append `Z` to a local/unzoned SEC value. Preserve reported filing date and report-period end as date-only fields (not invented midnight UTC). Separately record request start/response-received/assessment UTC, actual bounded response byte hash, reviewed source/schema/rights document versions and exact CIK/accession/document reference. Server receipt time is not filing time or market time. Hashing a response proves neither origin/finality nor redistribution rights. No onchain finality applies. No raw hash has been observed in this task.

Fresh retrieval can describe a very old filing. Display that dated period and original filing age, never “live/current fundamentals”. A response receipt older than24h is stale under our proposed diagnostic policy; this does not make a quarter-old report “fresh fundamentals” when fetched today. Scope is partial recent supported-form metadata, not exhaustive history or a promise there was no newer material event. Amendments remain marked; neither a latest-array-tail guess nor a last-wins accession overwrite reconstructs restated financial facts.

**Rights/attribution/retention before GO:** the current policy must specifically support private **business** research, selected factual metadata/citation and chosen hash/decision linkage retention. Personal-use permission is insufficient. Record separate yes/no/unresolved answers for raw response, normalized metadata, long-lived decisions/hashes, private sharing and eventual public/commercial reports. Public/commercial redistribution is **excluded** from P1 even if private use is confirmed. Attribution must use actual source-required text and link, not an invented approved logo/notice. Government authorship, factual character, no-key access and free hosting are not substituted for a rights assessment; issuer-authored filings/exhibits can differ from government-authored material. If unclear, obtain explicit written clarification; none was requested/sent here. Personalized commercial security recommendations also require separate legal review, not just a “research” disclaimer.

Proposed P1 raw/normalized data handling is **session memory only, no server database, no decision-journal write, no raw payload application logs, no telemetry/training, no CDN/browser persistent cache or source export**. An initial session ends within15min; owner may cancel earlier. That is a design bound, **not a proven physical-erasure promise**: runtime/browser memory, BFCache/session restoration, crash dumps, tracing, provider logs, URL/access logs, replicas, WAL/PITR and backup copies must be inventoried and their retention reconciled with actual permission. No existing Neon storage is authorized. If a runtime writes logs/backups, “no SQL” and a logical TTL do not remove those copies. Unproven physical retention or an incompatible provider restriction =NO-GO. Persisting even a hash or derived decision link requires separately approved retention; this pilot cannot silently create a permanent evidence ledger.

A successful authorized future session would prove one genuine issuer metadata response and a truthful dated citation, **not** API availability/reliability for every asset, predictive edge, a financial-fact normalization contract or commercial rights. Report actual request/attempt count, identity result, original clocks, returned/supported row counts, bounded coverage, source hash, failure/cancellation and data disposition. Missing evidence stays missing. No such session/results exist yet.
