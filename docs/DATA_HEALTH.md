## Observation and coverage methodology

Per token the dashboard shows latest actual nonfuture observation, age, unique and stored counts, 24h/7d coverage status, quality notes and evidence links. Freshness thresholds are current through 75 minutes, delayed above 75 minutes through three hours, stale above three hours. Invalid latest quote/provider identity creates a quality barrier; a stale provider generation also makes the record stale. Missing observations and unavailable sources are explicit states. A fresh record does not imply complete coverage.

Coverage reuses [HISTORY.md](HISTORY.md): actual boundary points, required baseline, at-most-two-hour interior gaps, valid counters/provenance and no reset bridging. Operational coverage additionally checks explicit allowlisted quote identity. Stale/source-failed coverage is withheld. Counts, actual span and maximum gap remain visible, without publishing financial totals. “Complete” describes these recorded-data safeguards, not independent transaction reconciliation. Signal Lab's stricter matched-period rules and existing calculations remain unchanged.

Expected missing slots count calendar minute-17 opportunities after the latest observation, with **15-minute scheduling grace**, capped at 168 (one week). This estimates absence of newer records, **not confirmed failed/missed workflow runs**; without a starting observation it is unknown. Recovery with a genuinely new point resets this estimate. GitHub can delay or drop scheduled execution.

Daily audits become overdue after 26 hours; summaries older than three hours are explicitly overdue, with their original token outcomes still dated. Future diagnostic timestamps are rejected as usable current evidence. Matching a summary's exact expected dataset hash confirms matching content only: failed/skipped tokens remain failed/skipped. A mismatch can reflect independently cached revisions and does not prove a push failed.

## Bounded diagnostics and partial failures

The collector now writes an atomic `data/collection-summary.json` with start/finish time, safe event/run ID, exact expected snapshot hash, overall complete/partial/failed/skipped state, and at most ten per-mint outcomes. Reasons are a fixed enum: e.g. provider not found/rate limited, timeout, invalid JSON, identity mismatch, duplicate timestamp or recorded counter reset. Exception messages, response bodies, headers and arbitrary URLs are never logged. Unknown metadata is stripped by server-side validation. Duplicates are skipped, resets remain genuine recorded barriers, and partial success persists only actual successful records. All-failed collection writes diagnostics and keeps the workflow failed; all-skipped collection does not invent observations. Existing provider validation and counter calculations are preserved.

The collector job is main-only, five-minute bounded, serializes with the audit, and explicitly pushes `HEAD:main`. Commit/push errors fail the job; there is no force push or blind retry/rebase. Both snapshot and summary are retained in seven-day artifacts even after failure. A summary hash is an expectation before publication, not an assertion that publication succeeded. The dashboard separately shows collection and persistence steps, audited dataset commit and content match. Historical manual push confirmations remain dated log evidence; future audits do not fabricate log confirmations.

The new daily 07:43 UTC audit performs at most six bounded GETs: workflow state, twelve recent runs, scheduled count, at most three latest-run jobs, latest snapshot commit and its exact bytes. API responses are capped at 1 MiB, snapshot at 2 MiB, requests timeout after eight seconds, redirects are rejected, and the job has a five-minute limit. Partial/API failure produces `unavailable`, never a false zero count. Audit evidence is published separately without collecting rewards. The server uses fixed raw GitHub URLs for history, audit and attempt summaries, sharing the bounded source implementation: five-minute per-instance cache, eight-second request deadline, one-minute failure backoff, at most 15-minute last-success retention, no redirects, transport-age validation, SHA-256 exact bytes, 2 MiB history / 64 KiB diagnostic limits. Retained diagnostic evidence keeps original times and source warnings. No client-controlled source URLs or unattended browser polling exist.

## Optional alerting, cost and security

Alerts default **off**. A human may set repository variable `SCOUT_DATA_HEALTH_ALERTS=true` after review. Only the first attempt of the daily scheduled audit can deliberately fail for operational data failure: an unavailable audit or a token whose usable source/quote/counter observation (including provider time when present) is more than six hours old; missing records receive six-hour grace from verification. No reward amount, price, velocity or trading condition participates. Manual dispatch and reruns do not trigger this optional alert step. Native GitHub Actions failure notifications depend on each user's notification settings; there is no webhook, email integration, additional secret or paid service. Ordinary workflow errors can still cause normal GitHub notifications independently of this optional feature.

**A monitor on the same GitHub scheduler cannot notify if scheduling itself stops.** This is a low-cost visibility mechanism, not an externally guaranteed pager or uptime monitor. A daily audit also cannot reconstruct every hourly failure between audits. Human inspection remains necessary for scheduler outages.

Only the audit job uses the existing ephemeral GitHub token, with `actions: read` and `contents: write`; collector retains its existing contents-write permission. Credentials are sent only to the fixed GitHub API origin, never raw GitHub, redirects, public output or browsers. Main-only guards and reviewed branch protection remain essential; restrictive branch rules can block publication and must not be weakened silently. Artifacts contain public observations/sanitized diagnostics, not provider credentials. No dependencies, paid integrations, DNS or infrastructure are added.

Existing hourly jobs now store one bounded summary and retain public artifacts seven days; audit adds one short daily job and up to six requests. Actions minutes/storage, hosting egress and cold-start instance multiplication still consume existing quotas. At most three fixed source files are read per cache cycle; failure backoff bounds repeated reads. Artifact copies can approach 336 MiB at the 2 MiB history ceiling over 168 hourly runs, before compression. Review quotas and history growth; do not silently increase limits or add secrets.
