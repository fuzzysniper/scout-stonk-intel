## The experience

Paste an exact Solana address, then explicitly choose **Analyze token**. Pasting does not submit, trim, extract or log the address. Names/tickers/links, whitespace and repeated mint parameters remain invalid. A valid address requests the two existing same-origin endpoints once: `/api/mint-facts?mint=<exact>` and `/api/token?mint=<exact>`. No provider URL or credential is selected by the browser. Direct exact-mint links request the same independent checks after hydration; sharing does not freeze an observation.

The first accepted onchain answer shows the full original mint, exact token-unit supply, standard mint/freeze controls, Token Program versus Token-2022, finalized context slot and original checked time. A short “check(s) need attention” link leads directly to **What needs attention**. This is a count of triggered review items, not a safety grade or count of every possible control. Each concern shows a plain explanation; “Why this is flagged” contains its exact field/value, mint, slot, server UTC, source host and response SHA-256. No inferred signer identity, project endorsement or malicious-intent verdict.

**Market evidence** follows in the same result. It uses the existing exact-mint adapter/client and its bounded projection. A reported pool, exact base/quote identities, separately attributed provider label and original retrieval clock are distinct from mint-account facts. Quote-side results describe another base asset; its figures never become the requested token's performance. Missing, rejected, incomplete, wrong-identity, future-clock, dated and rate-limited results remain explicit. An unavailable market source does not erase accepted onchain facts, and an accepted pool does not verify the blockchain account or project.

**Still unknown** always explains holder concentration/insider allocations, related wallets, LP control/locks/removability, transfer/sellability, distribution/entitlement, asset backing and realized returns. No new source checks those properties. Source failures never become reassuring defaults, zero figures, token-risk flags or a rug-pull verdict.

Copy/share keeps the exact case-sensitive address. The first panel preserves its exact-mint research link and clipboard fallback; the market section adds direct mint copying with a truthful native-copy fallback. Editing keeps the result's original identity until submission; replacement/unmount aborts or discards old source work. Back/forward, search cancellation and manual cooldown recovery remain supported. Local clock timers age evidence; they do not poll providers or retry requests.

The three October 14 StonkFun examples and all original source receipts/rights gates remain. When a current mint check succeeds it leads the answer and their stale provider explanation is in a separately dated disclosure. When no current facts are accepted, those selected examples retain their clearly stale explanation and separate failed-current-check status. They never establish current rewards, equity/gold ownership or holder payments. `/terminal`, research, existing APIs and CARDS discovery remain; CARDS is a secondary footer research entry, not a default lookup universe.

## What users get after Agent B's backend is operational

No consumer activation or contract change is needed. The unchanged `projectMintFacts` boundary accepts only HTTP 200, matching initialized exact-mint mainnet facts, approved program/layout/precision and consistent authority interpretation, `acquisition: production_rpc` with exactly `mainnet.helius-rpc.com`, finalized context slot, source hash and the existing original-clock/freshness checks. It preserves exact u64/decimal supply and reviewed/unreviewed Token-2022 limitations. A cache evaluation timestamp does not refresh the 60-second observation.

An authorized canary mint then renders those genuine fields and derives only the concerns justified by its actual response. Other mints may remain denied/disabled during the server-owned canary; that is **not** a token verdict. Later server-approved wider availability uses the same UI and validator. This PR adds no client allowlist, source switch, query activation flag or fallback RPC. It neither assumes Neon/Helius is active nor supplies an authentic canary observation. Every successful test here is labeled synthetic/offline, including offline replay of the production discriminator. A synthetic, recorded or development discriminator never becomes production facts.

Even after Helius is operational, this method does **not** establish market value, holder distribution, project identity, last mint-change time, liquidity control, transfers, stock ownership, payout rights or a profitable trade. `contextSlot` is a snapshot boundary, not the last mutation; `checkedAt` is a server clock, not Solana slot time. Supply is not circulating float or anyone's balance.

## Market quantities and publication boundary

Liquidity, volume, price movement and market cap remain withheld in the new result. Existing `/api/token` exposes upstream fields, but does not supply actual market timestamps or an independently qualified cap/circulating-supply definition. Existing [rights research](../consumer-v19-research/README.md#access-and-publication-rights--separate-unresolved-gates) has not established financial retention/redistribution/commercial permission. The consumer reuses `watchReport`, which discards every financial quantity and arbitrary provider link. There is no UI/query/environment approval override. No cap/price trend, relative ranking, quote conversion, holder ROI or liquidity-based concern is derived.

The market response's retrieval time is explicitly a host fetch clock. It may be generated while the existing server cache still holds an earlier provider response. Recent retrieval therefore does not establish a fresh price. After 60 seconds this view calls it a dated **response**, without changing its original timestamp or token role. Self-paired/pool-aliased and mismatched identities fail closed. Pool identity and quote role are never joined by ticker or assumed to be CARDS/StonkFun membership.

One bounded read-only local production `/api/token` probe on 20 Oct returned HTTP 200 and passed the existing consumer identity projector; no body, pool fields or financial values were published. The projection checks exact requested mint/source/clock and, if present, exact base/quote/pool membership. No current price, positive pool match or authentic Helius result is inferred from that technical success alone. See [actual QA](QA.md).

Automatic approval review rejected a proposed source-derived market screenshot/receipt because publication rights remain unverified. The safer completed probe emitted technical status/validation only, with no source-data artifacts. Committed result screenshots therefore use labeled offline fixtures; they are actual Chromium production renders, not authentic market or onchain observations. Public GET success is not permission to publish quantities or source-derived captures. Existing API financial JSON in Network remains unchanged; this display withholding does not remediate prior API rights questions.

## Scope, risks and rollback

Changed only consumer components/styles, scoped consumer tests/harness/config and these docs. No API/shared contract, backend, database, dependency, collector, workflow, RPC, security/deployment setting, Cloudflare, credential, wallet or treasury change. No new scraper, stored watchlist, public collector, schedule, trading action or source integration.

Risks/limits: market rights/timestamps remain unresolved; selected pool coverage is incomplete and mutable; standard authority presence is not proof of abuse, absence not proof of unrestricted transfers; extension review is deliberately partial; RPC report is not independent replay; browser clock errors may withhold otherwise valid observations; shared URLs reveal requested addresses in ordinary server logs. No private position or founder watch mint is committed. No physical iPhone or human comprehension study was performed.

Rollback: revert this consumer PR. That removes the composed concern/market/unknown sections and restores the prior lookup-button copy and OnchainCheck usage; independent backend/contracts, immutable data, archive, secondary CARDS routes and all infrastructure remain intact. No data migration, credential rollback or live service action exists. Human review only, no merge/manual deployment or backend activation.
