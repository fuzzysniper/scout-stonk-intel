## Actual limits and semantics

Scope hash is exported by `lib/live-ledger/policy.mjs` and pinned in SQL. One Pump.fun creation program, one active fenced lease, one source connection, ≤1h grant, ≤3 connection attempts, each precharged for **20,000 frames /16MiB**, ≤40 HTTP reads capped **1MiB each** (A enforces native byte/time/no-retry limits), ≤20 finalized promotions, 200 normalized records, last20 read. Credits are integer owner-verified weights and cap; zero/unknown rates cannot authorize. No monetary estimate is asserted; maximum modeled credits = `min(credit_limit,3*connection_credits+40*rpc_credits)`. Owner must confirm worst-case per-connection weight covers all frames/bytes and provider billing rules, including errors/unsolicited traffic. Stop local receive at cap; bytes already in transit/remote billing cannot be undone by a ledger.

Reservations commit before provider I/O. Timeout/crash/uncertain acknowledgment never refunds a ticket. Admission, quota, fence and STOP are one row-locked PostgreSQL transaction with synchronous commit. Native TLS peer/hostname/protocol, exact restricted role, privilege isolation and all function body hashes are checked in every transaction. No migration, retry, alternate provider, memory limiter or budget reset exists in runtime. Pool size1, role connection cap2, connection timeout1s, query1.5s, transaction deadline3s, SQL700ms/lock200ms. DB outage is unavailable/unknown, never an empty-success feed.

Lease12s, A polls heartbeat every1s and must close source on denial/storage error/expiry. A's own monotonic timer is essential if a process pauses. An expired **unclean** lease latches STOP, never admits a second worker. Clean native close must precede release; terminal release clears fence, reconnect release retains it. Socket-close attestation comes from A's native transport, not PostgreSQL. A may acknowledge only an exact fenced native closure after STOP; `closed_after_stop` clears the lease only on terminal release and leaves STOP/all budgets permanent. The store cannot physically close a paused process's socket or cancel an already admitted HTTP read; STOP prevents future reservations and A terminates in-flight work. Confirm closure and pause Render independently on emergency. Never “recover” by clearing STOP/fence or scaling a replacement.

`receivedAt` is original worker receipt UTC, not block time. `checkedAt` is verification completion UTC, `blockTime` is nullable RPC-reported chain time. Hashes are of A's original raw bytes, not reconstructed JSON. Native driver reports actual SQL server clock. Database heartbeat does not prove source health: source state, last frame, last pong and latest RPC duration are separate. Receipt/pong older45s cannot show observing; gaps explicitly begin/end; duplicates retain original identity/clock and do not imply another sample. Retained counts cover only this bounded stream, no complete-market coverage or financial signal.

## Retention, monitoring and rollback

No raw logs, transaction bodies, provider URLs, keys, prices or financial quantities are stored. Normalized records expire from reads after **1h from first receipt**; first-seen upgrades never extend TTL. Physical purge runs on admitted worker transactions, with a hard 200-row cap. **This is not a guaranteed wall-clock physical purge after worker/DB outage or STOP.** Owner must approve this distinction and database backup retention; if rights require guaranteed physical deletion by a deadline, do not activate until that is separately implemented/approved. On shutdown, owner reviews/purges expired normalized rows via the separately authorized cleanup below. Durable quota/STOP/gap/error counters have no auto-expiry or reset.

Monitor through authenticated snapshot: state, lease/DB heartbeat, provider frame/pong age, source gap begin/end, errors, reservation usage versus cap, record expiration and event/finality hashes. Do not export raw HTTP errors, DSNs, authorization headers, key values, socket URLs or PostgreSQL connection errors to logs/alerts. Record categorical failure only. Unknown host status is not healthy. A worker crash, DB failure, credit exhaustion, unexpected source, malformed/uncertain reply or retention/protection failure means STOP/no reconnect. Monitoring must not call the provider itself.

Rollback: authenticated STOP first, verify committed stopped snapshot, confirm A's native closure and **owner-approved** pause of the dedicated Render service. If DB unavailable, pause worker/disable DATA key only under owner incident approval; preserve counters and ambiguous attempt evidence. Turn the new API flag false through separately approved normal release/config path. Leave all existing mint gates, schemas, admission counters, aliases, credentials, collector and bot unchanged. Do not drop/reset live control or grant a new session to bypass spent budget. Owner-only cleanup of expired records, if separately authorized: `DELETE FROM scout_live.events WHERE expires_at <= clock_timestamp();` (never control). Review backup retention and final sanitized evidence before any separately approved eventual role/schema removal.
