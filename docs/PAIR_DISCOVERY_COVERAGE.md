## Backward-compatible opt-in

- Existing `/api/pairs` and `/api/pairs?quoteMint=<mint>` continue to read/filter the **global two-page cached sample locally**. No surprise provider request per existing quote selection.
- New `/api/pairs?quoteMint=<mint>&discovery=pair` requests **that exact quote at the provider**, within the same two-page/25-record and12-mode-check limits. No mode/search/page/limit/cursor/arbitrary-source parameter is added.
- Repeated, unsupported or missing quote/discovery parameters return400 before source access. A verified registry miss returns the existing structured404 after a registry read, without a token query. Registry failure is503, not an unverified404.
- Keep schemaVersion1, dataset.scope=`bounded_official_catalog`, existing group/token fields, strict identity verification, market/history provenance and all financial gates. No frontend adoption is necessary for #42's default integration.
- Optional additive `dataset.coverage.discovery` states `strategy: 'global_sample' | 'provider_quote_mint'`, `quoteMint: string | null`, `providerReportedTotalScope: 'catalog' | 'quote_mint'`. Global strategy has quoteMint=null even for a local output filter. Scoped strategy has the requested exact mint. This field is absent when no source snapshot is usable;503 never claims successful discovery.
- `complete:false`, `atomic:false` **always remain false**, even when a small provider-reported result fits one page. The new total refers to that upstream quote query, not the whole market or synchronized reward-history coverage.

For scoped reads, **any mismatched quote mint rejects the whole page**, rather than filtering it locally and falsely calling it pair discovery. Short results inconsistent with page/total are also rejected. A first-page failure returns503; a bad second page retains only validated first-page evidence with degraded status and warnings. Identity/symbol/program/pool/mode, byte/time/transport bounds, rejected-record handling and official aggregate verification remain enforced. No fallback to the global sample under the scoped label.

## Completeness, quality and expected cost

The provider describes live platform pools, not every historical launch or every asset anywhere. Two pages cover only the first50 market-cap-selected records **within the requested quote**. Ranking selection is sampling bias, not a SCOUT return ranking. Page positions can shift; there is no documented catalog snapshot/cursor guarantee. The manual NVDAX total7653 became7654 during the later local API proof. Global total178046 was larger than Day1's dated178028. Stable totals across two adjacent calls would still not prove an atomic snapshot or unique exhaustive enumeration.

Cold scoped read: at most1 registry +2 catalog +12 aggregate mode GETs = **15 attempted provider reads**, maximum three concurrent mode checks, cumulative1 MiB, three-second per-source and ten-second overall deadlines. Warm reads of the same scope coalesce/cache for five minutes and make zero provider reads. Mode checks prioritize tracked identities then mint order; unchecked tokens stay catalog_only, not falsely verified.

Scoped admission retains at most **four quote readers per process**, does not evict warm entries to serve arbitrary new mints, and allows at most **one cold scoped refresh per minute per process**, including failed attempts. Capacity, admission or cooldown refusal is structured503 with no usable snapshot. Expired idle entries can be reused; in-flight readers cannot be evicted. Existing global refresh budget remains unchanged. Shared429 cooldown covers global and scoped readers; numeric Retry-After up to3600s is honored, missing means60s, unsupported/long/date-form waits pause the instance rather than shortening a provider delay. Already-valid warm cache can be served without new network access.

These are process limits, not a distributed IP-wide quota. Multiple replicas and other consumers can share an IP;429 still fails closed. No paid provider, key, indexing database, recurring collector, global crawl or billing assumption. Client adoption/production rollout remains a separate human decision; this PR neither deploys nor activates anything.
