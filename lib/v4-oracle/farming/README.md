## Trust, source clocks and bounds

This is a pure projection of **provided normalized observations**, not a raw RPC parser, signature verifier, independent ledger replay or proof of provider authenticity. A syntactically valid hash/rights receipt/`complete` assertion does not authenticate bytes or license data. A separately reviewed server-side decoder must hash original bytes, verify successful finalized transactions, supported token/pool instructions and post-balances, bind exact original mint/quote/pool/units, and substantiate completeness/rights before calling it. Never accept the typed observation object from an untrusted client as verified evidence. JSON must already reject duplicate keys and preserve integer lexemes upstream.

Every area requires a matching exact32-byte mint and complete declared coverage. Each transaction requires an explicit succeeded outcome and carries its own64-byte signature, instruction index, finalized slot, original block clock and source reference. Different instructions in one transaction are different events; duplicate signature+instruction pairs within an event list are rejected. Same-slot/same-time does not establish a bundle. Conflicting base/quote units withhold all areas; invalid independent evidence withholds the affected area. Token-account mints and trade/pool quote identities are checked independently of the envelope.

`sourceAt` is typed by `clockKind`: `provider_as_of` means the source's explicitly asserted record cutoff, while `finalized_block_time` is the **corroborated estimated block time for that reference's contextSlot**, not a record update or account mutation timestamp. RPC context slot alone has no UTC clock. Null blockTime, no reliable index cutoff, or receipt substituted for a source clock => missing observation/GRAY. `receivedAt` is actual acquisition receipt, `asOf` trusted evaluation time. Source <= receipt <= evaluation; evaluated source age <=120s for the envelope/classifications; covered end <= source and no more than120s behind it. These are code freshness thresholds, not latency promises. Historical transaction/snapshot clocks can be older; they must match the bounded historical interval/boundaries, not be relabeled fresh.

No silent partial pages: `partial` or `unavailable`, cutoff/retention gaps, wrong network/finality, stale source, rights restrictions, missing hashes/paths, inconsistent amounts or uncertain pool decoding => GRAY, categorical withheld reason, no zero fabrication. A complete all-account snapshot must reconcile exactly to supply. A complete largest-account **sample** remains incomplete token-wide distribution and cannot produce GREEN. Verified pool/vault/CEX/platform exclusions must name included accounts, match the snapshot slot, have timely source classification and independent approved evidence. Never exclude a large account just because it looks inconvenient.

Snapshot balances are end-of-slot balances. Exit/pool interval events must be strictly after the opening slot through the closing slot; opening-slot events cannot be counted twice. Exit arithmetic reconciles every tracked wallet including buys and transfers; transfer out is not a sell. Anchor `firstObservedBuy` means a decoded buy observed by the declared cutoff, never the first-ever or complete launch cohort. Trade cohorts compare [from,splitAt) with [splitAt,to], bounded additionally by declared finalized slots; completeness is relative to the declared discovery domain, not all venues/people. A returning/new-to-history buyer is a distinct address, not a distinct owner. Quantities are base raw units or the exact quote raw units; SOL funding is lamports.

Limits:512 rows per array,32 tracked funding/exit wallets,16 declared cohort pools,24h interval,18 decimal places, canonical uint64 per raw quantity, depth16,40,000 JSON nodes and1,000,000 aggregate string characters; no accessors/exotic objects/sparse arrays/cycles. The bounded funding pair comparison is at most130,816 pairs. Sums/ratios use BigInt (bounded by the row budgets); no floating financial arithmetic. No partial acceptance after a budget failure. Actual Solana mints with decimals above18 are unsupported here, not silently rounded.
