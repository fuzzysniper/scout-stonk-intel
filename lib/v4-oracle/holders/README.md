## Executable path

1. `largestRequest(exactMint)` builds finalized `getTokenLargestAccounts` (id260001), at most20 returned token-account addresses. No pagination/holder sweep.
2. `accountsRequest(exactMint, selectedAddresses, selectionSlot)` builds finalized/base64 `getMultipleAccounts([mint,...selected<=20], minContextSlot=selectionSlot)` (id260002). **Supply is decoded from the mint in this same response**, not a differently timed getTokenSupply. Original mint and each token-account buffer are hashed and decoded; account-array order must match the original request. Mint/program, amount, owner authority, state and units are retained. No separate supply request is needed.
3. `clockRequest(snapshotSlot)` builds `getBlockTime` (id260003). Retain its independent original response hash/path. Estimated production time is NOT an account mutation time, RPC receipt or HTTP Date.
4. `decodeHolderCapture(HolderCapture)` owns copies of raw byte buffers, validates exact request payloads, response IDs/lexemes/shape, clocks, identity, binary layout, rights and bounded contexts; returns an opaque process-local HolderEvidence capability. `inspectHolderEvidence(cap)` exposes its frozen candidate/result. JSON/spread/casts cannot fabricate a capability. Extra `native`, hash or providerAuthenticated flags are rejected.
5. Only a successfully decoded, supported, positive-denominator sample becomes a canonical `Observation<HolderData>` passed through the **unchanged** farm projector. Always `population=largest_token_accounts`; complete refers ONLY to the requested list, never token-wide coverage. `analysis` is technical candidate analysis, not authenticated live findings.

This implements the raw-data-to-engine path rather than accepting unverified supplied percentages or caller-built financial observations. **It does not authenticate a remote provider.** Request/body/hash agreement is not TLS identity or owner/admission proof. Fixed IDs correlate this three-step recipe; they are not secrets or cryptographic request identities. The response does not echo the queried mint/address list; native authority must bind the actual server-owned original request. The capture constructor only accepts synthetic_fixture/recorded_response, never native_https. `providerAuthenticated` is permanently false. Valid response/hash/host strings cannot change it.

## Honest coverage / timing / arithmetic

- At most20 TOKEN ACCOUNTS, not all holders, wallet entities or beneficial owners. Multiple token accounts may have one token-owner authority; that pubkey may itself be a program, service or custodian. No owner aggregation/insider/common-control inference. Decoded token-owner authority is distinct from the account's program owner.
- Mint + all selected account balances share the getMultipleAccounts **provider-reported** context slot. The selection call can precede it: minContextSlot is a lower bound, not an exact/historical-slot request or atomic cross-call proof. Both slots, selection amounts and balance changes are preserved. If slots differ, these are previously selected accounts, not a verified current largest20 list. Even equal slots are not independent chain replay. More than128-slot advance or same-slot contradictory amounts fails closed.
- Original request/response hashes, account-byte hashes, field paths and independent clock reference remain in the frozen result; raw response bodies are not returned/stored. No caller hash accepted. UTF8 errors, duplicate JSON keys, unsafe slots, rounded fractions, wrong programs/mints/request IDs, missing/null/closed accounts, truncated lists, malformed base64/binary/options/TLV, stale/future clocks, unsupported host/network or unreviewed/restricted rights fail unavailable/GRAY. No dropped account is silently zero-filled.
- Exact source Unix seconds from getBlockTime are an **estimate**, tied to snapshotSlot by the exact original request and clock response. Context slot alone supplies no UTC and receipt never substitutes for missing/null blockTime. Each response <=128KiB, account buffer <=8192bytes, read <=5s, three captures serial with >=2.5s start spacing and <=20s total acquisition, evaluated receipt age<=60s and source-block estimate age<=120s. These are qualification bounds, not a live traffic permit or evidence of runtime limiter enforcement.
- All balance/supply arithmetic uses canonical uint64 raw integers/BigInt; nonfinancial rentEpoch/lamports uint64 lexemes are validated without using rounded JS values for financial math. JSON UI amounts never replace raw bytes. Farm top-min(10,sampled accounts) numerator / exact mint supply is scoped account concentration; population is always a sample, never GREEN. This is not top20-share/all-holder distribution or a rug probability. No full-distribution, ROI, profit, real-demand or USD claim.
- No independent pool/CEX/vault/platform classifications are available from these three reads: exclusions are empty, no account is guessed away. Verified classifications would need a separate reviewed original-source capability; public labels or large balances do not suffice.
- Empty selected list and genuine zero supply are retained as observed raw values but have no invented percentage. Native/wrapped SOL has incomparable mint-supply semantics and is withheld from the concentration denominator. First mint-proof SOL success is NOT holder-distribution success.
- Token2022 is separate: base mint/account layouts and account type/TLV are checked. Extension-free Token2022 plus the reviewed zero-length ImmutableOwner account extension can supply raw sampled balances. Other mint/account extensions (including fees, confidential/scaled/interest/hook states) preserve raw hashes and extension IDs but withhold financial concentration pending independent review. Unknown never borrows SPL confidence; frozen accounts remain in balances, not presumed sellable.
